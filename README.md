# GCS_WITH_AVIONICS — Ground Control Station

Ground Control Station (GCS) for the IN-SPACe / ASI model rocketry competition.  
The system receives telemetry over a 915 MHz or 433 MHz radio link (USB–serial),  
parses Annexure‑2 CSV packets in C++, logs them to `Flight_<TEAM_ID>.csv`, and  
streams live telemetry to a web dashboard for real‑time plots.

## Features

- C++17 backend, Windows‑first (Visual Studio / MSVC, CMake).
- Serial input from telemetry radio (e.g. SiK/3DR‑style 915 MHz/433 MHz).
- Annexure‑2 compliant telemetry format:
  - `TEAM_ID,TIME_STAMPING,PACKET_COUNT,ALTITUDE,PRESSURE,TEMP,VOLTAGE,GNSS_TIME,GNSS_LATITUDE,GNSS_LONGITUDE,GNSS_ALTITUDE,GNSS_SATS,ACCELEROMETER_DATA,GYRO_SPIN_RATE,FLIGHT_SOFTWARE_STATE,OPTIONAL_DATA`
- CSV logger:
  - Produces `Flight_<TEAM_ID>.csv` with exact header order.
- SSE (Server‑Sent Events) stream:
  - Backend exposes `http://127.0.0.1:<SSE_PORT>/events` (default `9090`).
- HTML/JS/CSS frontend:
  - Uses Chart.js to display altitude, pressure, temperature, voltage,
    GNSS sats, and accelerometer data in near real‑time.
- Designed to satisfy competition ground‑station requirements:
  - Real‑time telemetry display.
  - Logging of all packets for post‑flight analysis.
  - SI units, proper headers, and team ID.

## Backend — Build & Run (Windows)

### Prerequisites

- Windows 10/11 (x64).
- Visual Studio 2022 or Build Tools (MSVC, Windows SDK).
- CMake 3.20+.
- A telemetry radio receiver connected via USB (COM port).

### Configure & Build

Open **x64 Native Tools Command Prompt for VS 2022** (or equivalent), then:

```
cd GCS_WITH_AVIONICS\backend
mkdir build
cd build
cmake .. -A x64
cmake --build . --config Release
```

The backend executable will be created as:

```
backend/build/Release/gcs_backend.exe
```

### Run Backend

1. Find the COM port of your telemetry receiver (Device Manager → Ports (COM & LPT)).
2. Start the backend with the correct COM port, baud rate, and team ID:

```
cd GCS_WITH_AVIONICS\backend\build\Release

.\gcs_backend.exe ^
  --serial COM11 ^
  --baud 115200 ^
  --team "2024-ASI-XXX" ^
  --send-start
```

Options:

- `--serial` : serial port name, e.g. `COM5`, `COM11`.
- `--baud`   : UART baud rate (must match radio SERIAL_SPEED).
- `--team`   : team ID string, used in CSV filename `Flight_<TEAM_ID>.csv`.
- `--send-start` : optional, sends `START\n` once on connect.
- `--sse-port` : override SSE port (default `9090`).

If successful, you will see:

```
GCS backend running. Serial=COM11 baud=115200 team=2024-ASI-XXX SSE=http://127.0.0.1:9090/events
```

A CSV log file will be created in the working directory:

```
Flight_2024-ASI-XXX.csv
```

with header:

```
TEAM_ID,TIME_STAMPING,PACKET_COUNT,ALTITUDE,PRESSURE,TEMP,VOLTAGE,GNSS_TIME,GNSS_LATITUDE,GNSS_LONGITUDE,GNSS_ALTITUDE,GNSS_SATS,ACCELEROMETER_DATA,GYRO_SPIN_RATE,FLIGHT_SOFTWARE_STATE,OPTIONAL_DATA
```

## Frontend — Run Dashboard

The frontend is static HTML/JS/CSS and can be served with Python’s http server.

### Start local web server

In a **separate** terminal:

```
cd GCS_WITH_AVIONICS\frontend
python -m http.server 5500
```

Now open a browser (Chrome/Edge) and navigate to:

```
http://127.0.0.1:5500
```

The dashboard will:

- Connect via EventSource to `http://127.0.0.1:9090/events`.
- Display team, state, mission time, GNSS sats.
- Plot real‑time charts for altitude, pressure, temperature, voltage, sats,
  and the first accelerometer/orientation axis.

If you changed the SSE port with `--sse-port`, update `frontend/app.js`:

```
const evtUrl = 'http://127.0.0.1:9191/events'; // example
```

## Telemetry Format

The system expects one CSV line per packet in this exact order:

```
TEAM_ID,TIME_STAMPING,PACKET_COUNT,ALTITUDE,PRESSURE,TEMP,VOLTAGE,GNSS_TIME,
GNSS_LATITUDE,GNSS_LONGITUDE,GNSS_ALTITUDE,GNSS_SATS,ACCELEROMETER_DATA,
GYRO_SPIN_RATE,FLIGHT_SOFTWARE_STATE,OPTIONAL_DATA
```

Example line:

```
2024-ASI-XXX,23.000,14,0.000,468.0,27.0,11.00,23.000,18.2765,72.5623,50.0,11,0.89,-54.730,Idle,
```

- `ACCELEROMETER_DATA` accepts sub‑fields separated by `|`, `/`, `;` etc.
- `OPTIONAL_DATA` is free‑form and may contain additional info.

## Development Notes

- Backend is currently **Windows‑only** using Win32 serial APIs and WinSock2.
- SSE is a simple HTTP/1.1 text‑event-stream implementation.
- For Linux/macOS support, replace `SerialWin32` and `SseServerWin32` with
  termios and BSD sockets equivalents and adjust CMake.
